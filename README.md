# New Professional Lab final project
## _Дашборд для e-commerce кликстрима_

Необходимо подготовить данные для первичного анализа и собрать несколько графиков в дашборд, на котором условный "бизнес" может сделать выводы о данных


### Данные и инфраструктура

![image](https://github.com/user-attachments/assets/0e9d439a-2bba-4a13-a2f4-96e38bc52c7e)


Для реализации этой задачи была выбрана следующая архитектура:
**Airflow** -- Оркестрация пайплайна данных. Даг состоит из следующих этапов:
* generate_file_urls - генерация списка ссылок за 1 час из бакета S3
* download_files - скачивание файлов по раннее сгенерированным ссылкам
* unzip_and_add_metadata - разархивирование файлов и добавление в них метаданных с датой события
* load_data_to_clickhouse - записывает данные из файлов в Clickhouse в raw слой
* dbt_run - запускает контейнер с dbt, который трансформирует данные из core слоя в dm слой

![image](https://github.com/user-attachments/assets/ace87daa-7d6b-4fa0-b40a-ebb5b1b16d8d)


**Clickhouse** -- для хранения данных. Данные разложены по следующим слоям:
* raw - слой сырых данных
* core - очищенные и предобработанные данные
* dm - витрины, на основе который строятся дашборды в Superset

![image](https://github.com/user-attachments/assets/67b039a4-ff9e-4060-873f-4102c0ecb04e)


Скрипты для создания таблиц raw слоя и materialized view для core слоя можно посмотреть в файле. Витрины автоматически создаются с помощью dbt

**dbt** -- для трансформации данных между слоями

**Superset** -- для построения дашбордов

### Примеры и структура входных данных

##### Браузер и идентификаторы события

Здесь приходит timestamp (UTC), тип события, и два уникальных поля `event_id` и `click_id`, которые используются для
склеивания с другими данными. Пример записи:

```json
{
  "event_id": "8cca1c7d-b0cc-4738-be92-c644101e3fff",
  "event_timestamp": "2022-11-28 20:51:05.627882",
  "event_type": "pageview",
  "click_id": "811320f1-3bc2-42b9-a841-5a1e5a812f2d",
  "browser_name": "Chrome",
  "browser_user_agent": "Mozilla/5.0 (Linux; Android 2.3.5) AppleWebKit/531.2 (KHTML, like Gecko) Chrome/32.0.833.0 Safari/531.2",
  "browser_language": "sat_IN"
}
```

##### Информация об устройстве

Отсюда можно собрать данные об операционной системе и типе устройства. Склеить их с остальными данными можно по
полю `click_id`. Также в этих данных есть информация о пользователе. Пример записи (судя по операционной системе перед
нами путешественник из прошлого):

```json
{
  "click_id": "811320f1-3bc2-42b9-a841-5a1e5a812f2d",
  "os": "iPad; CPU iPad OS 4_2_1 like Mac OS X",
  "os_name": "iOS",
  "os_timezone": "Europe/Berlin",
  "device_type": "Mobile",
  "device_is_mobile": true,
  "user_custom_id": "aperry@yahoo.com",
  "user_domain_id": "1ab06c9f-0e2e-4f46-9b6c-91a0e9a86a4d"
}
```

##### Данные о геопозиции

Вам известно, что тут вам в базовом наборе дали только неточные данные, которые уже все события привязывают к
определённому городу. Склеивать с остальными наборами данных нужно по полю `click_id`. Пример записи:

```json
{
  "click_id": "811320f1-3bc2-42b9-a841-5a1e5a812f2d",
  "geo_latitude": "50.82709",
  "geo_longitude": "6.9747",
  "geo_country": "DE",
  "geo_timezone": "Europe/Berlin",
  "geo_region_name": "Wesseling",
  "ip_address": "206.227.30.186"
}
```

##### Информация о нахождении на сайте и откуда пользователь пришёл

В примере, который вам дали, явно фейковые данные, которые не соответствуют настоящему сайту, но поставщик данных
уверяет, что схема данных в реальной системе такая же. Склеивать с остальными данными можно по полю `event_id`. Помимо
непосредственно событий непосредственно посещения сайта, тут также маркетинговые метки. Пример записи:

```json
{
  "event_id": "8cca1c7d-b0cc-4738-be92-c644101e3fff",
  "page_url": "http://www.dummywebsite.com/home",
  "page_url_path": "/home",
  "referer_url": "www.facebook.com",
  "referer_medium": "internal",
  "utm_medium": "organic",
  "utm_source": "facebook",
  "utm_content": "ad_4",
  "utm_campaign": "campaign_2"
}
```

### Бизнес-логика:
* событием считаем переход пользователя со страницы на страницу
* покупкой считаем полный путь от страницы товара до страницы подтверждения внутри одной сессии:
    * переход со страницы товара (/product_*) на страницу корзины (/cart)
    * переход со страницы корзины (/cart) на страницу платежа (/payment)
    * переход со страницы платежа (/payment) на страницу подтверждения (/confirmation)


При этом, у нас могут быть за один полный цикл оплаты куплены несколько товаров, также внутри одной сессии может несколько раз совершён полный цикл покупки

## Установка и запуск

Все сервисы запускаются в своих docker-контейнерах
Абсолютно все параметры и переменные можно задать в файле **.env**

```
git clone git@github.com:ne1ega1/NPL_Project.git
```

```
cd NPL_Project
```

```
sudo chmod +x start.sh
```

```
./start.sh
```

После запуска будут подняты Airflow, Clickhouse, Superset и dbt
Airflow будет доступен по адресу http://localhost:8080
В базе уже будет создан дефолтный пользователь. Нужно только залогиниться и запустить DAG

Данные для входа:

> login: airflow

> password: airflow

Superset будет доступен по адресу http://localhost:8088
В базе уже будет создан дефолтный пользователь

Данные для входа:

> login: admin

> password: admin
